Starter kits

Three small apps that prove the SDK works.

Each kit is a single screen or script that sends a real request through the SDK to N-ATLaS. The three windows below are the kits themselves, running live. Clone one, swap in your own content, and run npm install && npm start.

01

Show the pipeline

Every intermediate step is visible, such as the transcript before the reply. Nothing is faked or swapped behind the scenes.

02

Label demo scale

Fixture datasets and shortcuts are marked "demo dataset" or "sample only" in the interface itself.

03

One shared look

Same layout skeleton across all three, so they read as one toolkit, not three unrelated demos.

Kit 01

Citizen Services

A single-page form for local-language Q&A over a small civic-info dataset, such as how to renew an ID. The language selector drives both prompt framing and language context.

SDK calls
normalizeText() → chat()
Shows
Language-aware prompting with injected context
Does not
Persist data, authenticate users or act as a real civic-info system

Kit 02

Education

A single-page tutor. The level selector shows the same chat() call reframed by prompt context, so you can see the SDK's flexibility without any new feature.

SDK calls
chat() · reportIssue()
Shows
Instructional framing by language and level
Does not
Track progress or store learner data

Kit 03

Customer Service

Voice-note intake with a drafted reply. It is the one kit that visibly chains transcribe() into chat(), so the whole pipeline is legible on one screen: voice in, transcript, draft response.

SDK calls
transcribe() → normalizeText() → chat() · reportIssue() · speak() (stretch)
Shows
Language-routed ASR feeding the LLM
Does not
Ship audio playback. Its absence is not a bug.

Run one against the live endpoint.

Point the kit at the OpenAtlas gateway with one environment variable. No separate deployment needed.
